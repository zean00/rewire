Background

The routing that open weights never shipped

Phase 0 finding

Hosted servers route modes; open weights don't

Frontier model servers quietly decide how to answer each request — a quick classification, a tool call, or a full generation ("auto" mode). That router lives on the server. The open-weights checkpoint ships no such router: every prompt gets the same pipeline, and the native default is think-always, then generate — a configuration our measurements show is the worst possible setting for agentic steps.

The substrate

Qwen3.5-4B — small, multimodal, hybrid

A 4B-parameter open model mixing standard attention with Gated DeltaNet linear-attention layers, with a native "thinking" mode. Small enough to run on one consumer GPU (RTX 5070 Ti, ≤9.6 GB), which makes per-step latency a first-class measurement — and makes the "does routing beat raw scale?" question honest: the comparison is always the model against itself.

The three regimes, as measurable mechanisms

DECIDE

Read, don't generate

Score a bounded candidate set directly from logits — first-token reads (D1) or teacher-forced sequence log-likelihoods (D2). Zero decode steps. Output is the choice itself, with a real probability distribution attached.

THINK

Spend tokens only where they pay

Ordinary autoregressive generation with the native thinking mode. Phase 2's filler-control showed thought continuity adds nothing (−6.5 pts); what pays is computation-shaped subtasks (arithmetic, value entry).

GATE

Calibrated confidence routing

Temperature-scaled decision confidence, fitted per domain on held-out calibration data, decides when to escalate. Escalation exchanges information (re-read richer context), not reasoning.

Goal

The question this PoC answers

“Can this PoC be better — speed and accuracy — at computer or browser use, compared to vanilla Qwen 4B — not aiming to compete with frontier models?”

That ambition was decomposed into three measured gates, each with a preregistered success criterion:

Gate A · MCQ (S8/Q12)

Can a gated decide/think hybrid beat all four vanilla baselines (never-think, no-think, think-always, naive hybrid) on 500 mixed-domain questions at equal or better latency?

Gate B · Browser replay

Does the mechanism transfer to web-agent steps — element selection on 1,801 replayed Mind2Web actions — against the same model's vanilla configs?

Gate C · Tool calls

Can the full user architecture — decide the tool → think the value → structured output — beat one-shot generation on complete, schema-valid actions?

  • Fairness rules: identical prompts and gates across arms, calibration on a disjoint split, matched-gate comparisons, per-item McNemar tests, per-item checkpointed runs.
  • Non-goal: frontier accuracy. The claim is strictly this model, routed, vs this model, vanilla.
Approach

One backbone, three output contracts, calibrated gates

What we did to the weights: nothing. The released Qwen3.5-4B checkpoint is loaded frozen (bf16, off-the-shelf) — no fine-tuning, no LoRA or adapters, no merged weights, no new special tokens, no training of any kind. Everything in this PoC is an inference-time layer wrapped around that frozen checkpoint: extra forward passes that read logits instead of generating (D1/D2 — zero decode steps), one line of prompt engineering (the format anchor), curve-fitted calibration (temperature scaling + acceptance thresholds fit on a held-out split — statistics, not gradient descent), and a deterministic control policy that decides when to escalate and how a turn assembles into a choice, a tool call, or text. Even THINK is the model's own native thinking mode — no distilled or SFT-trained traces. Consequently every comparison in this report is the same checkpoint against itself under different runtime policies; nothing here can be attributed to weight changes.

The decision reads

D1 · first-token read

Restrict logits to the candidates' first tokens — one forward pass, pure classification. Powers the fastest REFLEX-style routing.

D2 · sequence scoring

Teacher-force each candidate, score its sequence log-likelihood (α-normalized), softmax across candidates. Still zero decode steps; robust for multi-token candidates like web element lines.

  • Format anchor: a one-line format instruction lifts usable pre-mask probability mass from 0.016 → 0.912 — without it, the reads are unmeasurable.
  • Pre-mask validity: if the candidate set captures too little raw mass, the read is invalid — escalate rather than trust.
  • Calibration: confidence is temperature-scaled; the acceptance threshold is fitted per domain (ECE-minimising temperature, coverage/accuracy curve) — never assumed.

What was done

Three phases, every step measured

Phase 0 · Infrastructure

Runtime harness + the mode-probing baseline

uv-managed Python 3.12, torch 2.11 (CUDA sm_120), per-item checkpointed eval runners. Probed the model's native modes and found the open checkpoint has no mode routing at all — the gap this runtime fills.

Phase 1 · The read mechanism

Making logits measurable

First-token reads are dominated by formatting noise until the format anchor — pre-mask mass 0.016 → 0.912. D2 sequence scoring built and validated against D1. All later results stand on this.

Phase 2 · Escalation mechanisms

What escalation should actually do — including a kill

Preregistered kill criterion fired: think→re-decide's win is a policy win (a second read at a changed position), not thought continuity — a filler-thought control cost −6.5 points. Pivoted the escalation design to confidence-gated mode switching.

Phase 3 · Headline S8/Q12 · n=500

The hybrid beats every vanilla arm — SURVIVED

H-redecide 0.856 @ 0.26 s vs no-think 0.764 (McNemar 62/16, p≈3×10⁻⁷) and think-always 0.490 @ 17.3 s. Thinking retained only where it pays: pure accuracy on computation-heavy items still belongs to think-always (0.790 vs 0.660).

Browser phase · Gate B v1

Dataset build + first transplant: decide wins, MCQ hybrid fails

Built a Mind2Web replay harness (1,801 steps; element sets capped at 20; DOM-path + parent-text rendering after the first candidate representation collapsed both arms to ~0.20). Result: decide 0.320 vs vanilla 0.258 (p≈4×10⁻⁵) and vs think-always 0.115 (p≈6×10⁻¹¹) — but the MCQ hybrid's think→re-decide escalation was harmful on web (tail 0.188 vs 0.271); aborted honestly at n=78.

Browser phase · Gate B v2

Web-specific redesign: op-first, rich re-read, fitted gate

Op-first read conditions the element read; escalation swapped to a rich re-read of the top-3 with subtree/section context (zero think tokens); gate fitted on a calibration split (margin AUC 0.699). Escalation flipped from harmful to safe (+4.1 pts on the tail); gate separates 0.398 accepted vs 0.244 tail; decide vs vanilla p≈1.1×10⁻⁷.

Browser phase · Gate B v3

The tool-call chain, measured end-to-end

Chain (decide op → gated decide element → op re-read with options → think value → assembled call) vs one-shot JSON generation. First chain build lost (action 0.204) — the op stage saw less than the vanilla prompt; giving it the same context (op 0.507 → 0.843) flipped the result to a significant win (0.320 vs 0.274, p=0.0033). One-shot no-think JSON proved degenerate: CLICK on 896/900 steps. Mode router implemented and self-tested.

Browser phase · L1 · batched scoring

One prefix prefill, parity-gated, 5× faster

Collapsed ~20 sequential prefills into one shared-prefix prefill + tiled batched continuation scoring. A three-condition probe picks the cache strategy (crop-rewind is bit-lossy on Gated DeltaNet, so tile-and-batch wins); the parity gate passes: 0/50 argmax flips, pre-mask delta exactly 0, negative control separated 11×. Both web arms re-run batched: accuracy statistically identical (≥97.6% per-step agreement), p50 1.70 s → 0.34 s.

Browser phase · L2 live demo + L3 multimodal

The runtime, live in a real browser

Six-step trajectory on a staged site with live-DOM extraction — DECIDE (navigation; a pure 2-candidate dialog decision at 0.11 s), TOOL_CALL (op → gated target → op re-read → think value → executed), TEXT (accurate order summary). First runs scored 4/5; the tool-call miss was diagnosed live — the op read is a genuine three-way near-tie and committing to one op loses the correct branch — and fixed with a beam-over-ops chain (targets scored under every op, element-conditioned re-read arbitrating a log-linear product): 5/5, every action verified against its gold effect in-page. Along the way: root-caused and fixed a transformers generate() → stale rope_deltas poisoning that crashed the next cached scoring forward. S7: screenshot-conditioned decide reads score 0.960 = text-DOM 0.960 — the machinery is multimodal-ready.

What broke along the way (and was fixed in the open): a stale-checkpoint confound in the first headline run (caught by comparing first-decision confidences across arms; re-run clean) · causal-conv1d wheel ABI-incompatible with torch 2.11 (reference conv path) · prompt double-rendering of candidate lines · vanilla arms that never emitted the operation (unparseable op metric) · and the two scientific negatives above, kept as measured results.

Rubric reads (4-level) — the frozen bar says NOT PROMISING, but the floor disease is nearly cured where it matters. One pre-registered pass over all 815 probes, same evidence rule and grammar-forced recipe, E = Σ i·p over far/partly/nearly/fully done: the best frozen operating point is 56% det / 20% FA vs the required ≥67% / ≤13% — the binary read keeps the general dial. The pre-registered cuts tell the interesting story: on correct success claims (the t5/t1 "confident no on a true report" family), the binary reads p_done < 0.25 for 65% while the rubric reads E < 1.0 for only 9% (37/54 land at "nearly done"); on success claims the rubric at T=2.0 separates 62/24 where the binary separates 79/74; on failure claims the rubric detects 40% vs the binary's 7%. Recorded as dev-set leads only; nothing deploys; no iteration.
Prefix reuse for the reads — measured, and the fix is client-side, not a server flag. The build's slot selector is prefix-aware ("LCP similarity"): identical prompts dispatched sequentially re-evaluate 1 token each after the first (~170 ms vs 765 ms / 2,504 tokens — ~4.5× cheaper), zero flags. Both patterns the chain actually uses defeat it: parallel candidate dispatch splits across slots (both prefill in full), and the four review frames diverge at the first token, so LRU rotates and every read pays a full ~2.5k-token prefill. --cache-reuse 256 was measured: zero improvement. The levers are (a) dispatch the candidate reads sequentially and (b) restructure frame prompts so the shared evidence leads and the per-frame question trails — recorded as an infra lead; chain code unchanged.
Per-frame temperature fitting — demoted, and the reason is structural. The gate consumes raw read scores against thresholds, so any monotone rescale (temperature included) moves every score together and changes no operating point; the observed errors are saturated ties (0.0) in both directions, which no single temperature separates. The idea is retired from the "worth stealing" list.

Verdict

What this PoC concluded

Yes — the routed runtime beats vanilla Qwen 4B at browser use. Decisively against the model's own default (2.8–3.6× accuracy at 14–17× the speed), and significantly against the best vanilla configuration (+9.8 pts element accuracy, p≈8×10⁻⁹; +4.6 pts full tool-call accuracy, p=0.0033) — with zero parse failures by construction. The claim is this model against itself: routing and calibrated gates, not scale.
Conclusion 1

The default is the worst config

Think-always generation collapsed on every agentic metric (0.086–0.115 web elements, 79% unparseable JSON) while costing 14–17× latency. Every gain in this PoC came from routing away from the default.

Conclusion 2

Selection is classification

Pure decision reads beat generation at perception-selection tasks — twice, on independent designs, p≈10⁻⁷–10⁻¹¹. Answering from logits is more accurate and faster than writing prose.

Conclusion 3

Factorization needs context parity

The decide→think→generate chain beats one-shot output only after each stage was given the context the end-to-end prompt sees (op 0.507 → 0.843). The single most transferable engineering lesson of the PoC.

Conclusion 4

Gates are real, and domain-fitted

Calibrated confidence separates right from wrong steps (0.398 vs 0.244 on web; 0.882 fast path on MCQ) — but thresholds do not transfer across domains, and escalation must exchange information, not reasoning (rich re-read fixed what think-escalation broke).

Conclusion 5

Mode selection lives in the harness

The routing signal can gate escalation inside a mode but shouldn't pick modes — now measured directly (tab 4): a d2_over_modes read routes below the always-DECIDE constant (0.834 vs 0.844), sends 95% of value-needing steps down the choice contract, and costs −4.7 pts action accuracy; even a perfect mode router loses (−2.8) because declaring the contract is what enables the conditioned reads. The harness knows the affordances — that's the router — with auditable per-stage events.

Honest limits

What this does not claim

Accuracy evidence is offline Mind2Web replay; the live-browser work (staged-site demo 5/5, then 4 real sites / 20 steps at 0.90 adjudicated) exercises the runtime end-to-end but is not a benchmark — the real-site run is a signal-quality feasibility result (n=20, 2 genuine errors). The beam chain, now replay-measured, is a TYPE specialist: element +3.6 pts (p=0.021), action wash (p=1.0) — H3B stays the default. Value accuracy (0.600 exact replay / 9-of-9 live) measured on copy-from-task strings only. And the comparison is always Qwen 4B vs itself — better than its default, not frontier-class.

Does this transfer to other open models? Yes as a method, no as a config — three tiers:
1 · Machinery ports as-is. The harness only needs logits and a tokenizer, so any open-weights decoder LM runs it unchanged — nothing depends on the hybrid Gated DeltaNet backbone (closed APIs can't run D2 at all: teacher-forced scoring isn't expressible there).
2 · Numbers never port. Every constant — temperature, acceptance thresholds, pre-mask gates — was fit, not assumed, and provably doesn't transfer even across domains on the same model; a new model means re-running the calibration step (by design: calibration is a measured procedure, not a config).
3 · Effect size is the open question. The claim is "beats its own default" — a stronger open model writes better one-shot JSON and would narrow the gap, so the routing edge must be re-measured, though the "default is the worst agentic config" pattern is consistent with the wider literature.

Benchmark

MiniWoB++: 96 episodes, chain vs vanilla — and what the transcripts say

The decide chain and vanilla Gemma 4 12B ran the same 24 MiniWoB++ tasks on the same 2 deterministic seeds per task (48 episodes per arm, interleaved), scored by the environment's own reward — not by exit codes or self-reports.

Headline

A statistical tie

Chain 11/48 (23%) vs vanilla 10/48 (21%); paired per (task, seed): chain 5, vanilla 4, 39 ties. The interim "chain is worse" reading was small-sample noise. The chain costs 2.1× wall time (223 s vs 107 s) — mostly standing down: ANSWER was the top-1 op read on 79% of decide reads.

The asymmetry

Wrong is terminal, failed is free

MiniWoB scores a wrong action −1 and ends the episode; a failed action (selector miss, no-op) costs only time. The chain's mistakes are confident and terminal (29 wrong-action fails vs vanilla's 18); vanilla's stumbles are inert. Short-horizon click-games give the decision layer no room to pay for itself.

Four mechanisms, from the transcripts

1 · Submit-first ordering (9 sessions)

The first chain action is the terminal button before its prerequisite — submit before the form is filled, Login before credentials. The confident version of a safe intent, executed terminally.

2 · Refusal-as-payload (4 sessions)

The value composer emits "I am sorry, but I cannot provide the text…" — and the chain types the apology into the page.

3 · ANSWER stand-down (79% of reads)

283/359 decide reads say "no browser action needed" — the chain parks while the clock burns. The main source of the 2.1× latency.

4 · Matcher vocabulary gap (140 errors)

The click cell's selector covers links, buttons and submit inputs only — checkboxes and radios are unclickable. The 12B decide reads are near coin-flips here: mean top-1 confidence 0.340, median margin 0.048, 51% of reads inside a 5-point margin.

Safe fixes vs overfit traps → v3.14.4

The rule: MiniWoB scores abstention 0 above a wrong action −1 — so any timidity tweak raises the number while making the agent worse. Recalibrating ANSWER on MiniWoB outcomes, blacklisting Submit/Login labels, parsing the reward display: all rejected as overfitting in spirit. Two fixes qualified as bug-grade and domain-general:
1 · Refusal/empty-payload guard — an apology or empty value never fires; the turn passes through to the model instead. 15/15 probe sentences, including the trap ("I cannot say Vancouver" is a value, not a refusal).
2 · State-control coverage — the click matcher now covers checkboxes/radios with label and aria-name sources and prefers non-state controls on ties; TYPE is restricted to text-entry controls. End-to-end in a real browser: the old JS reproduces the benchmark's exact error; the new JS scores raw=1 on the failing episode, and passwords stay typable.

The checkpoint-review experiment — measured on both halves

The "review the model's thinking at each checkpoint" idea, run to a verdict: for every assistant claim that asserts world state, two grammar-forced reads against the newest page snapshot — does the evidence support this claim? (claim read) and did the attempted task succeed? (independent read). A brake = the asserted polarity contradicted by the independent read.

Labeled half

6 adjudicated sessions · 24 probes

Detection 6/9 (67%) on checkable wrong conclusions — but false alarms 2/4 (50%) on correct ones. The claim and independent reads are correlated: same model, same evidence, same blind spots. The second read inherits the first's mistakes.

Objective half

96 benchmark sessions · 815 probes · CDP ground truth

Brake catches 117/175 (67%) of wrong-polarity claims with 18% false alarms; on final-report claims, 77% detection / 32% FA. The claim read alone is uninformative (50%/48%). Threshold curve is shallow: 0.5 → 67%/18%, 0.05 → 47%/6%.

Verdict: real review signal — 77% of false success reports get flagged by a second read of the page — but not deployable as an automatic gate at this model size (a third of correct final reports would be challenged; 59% on chain sessions). The deployable forms: a log-only review flag for a second look, or grounding the brake in the objective evidence the harness already has (the CDP reward) rather than another self-read.

v3.15.0 — the six-lever hygiene pass, under an explicit overfit audit

The audit rule, applied to every change before it shipped: MiniWoB scores abstaining (0) above wrong action (−1), so any timidity tweak would raise the score while making the agent worse. A change is accepted only if it reads page structure and task text (never reward or benchmark vocabulary), is judged on held-out criteria (offline suites + the real-site sweep — MiniWoB reported as sanity only), and can fail honestly in both directions.

2026-09-22 — single-model framing backtest: vary the question, not the model

The experiment. Constraint: one model, no second opinion. Question: is the completion check's weakness the model, or the frame it reads through? The 596 ground-truth probes were re-read by the same 12B through three framings: GOAL (evidence + the task's goal line), DELTA (before/after snapshots — change evidence), COND (evidence + the stored claim-read verdict). Same forced-read recipe, ~35 min, 815/815 rows. The framings disagree with each other by 0.18–0.28 of probability mass on average — the same model, asked differently, decorrelates from itself.
The result (T=0.5, all-polar det / FA). Baseline 67% / 18%. GOAL 69 / 18. DELTA 57 / 13 (the conservative veto). COND 74 / 16. min(GOAL, DELTA, COND): 78% / 17% — eleven more wrong claims caught at the same false-alarm rate, no second model, ~2 s of extra reading. On chain sessions the GOAL read alone moves 66/34 → 78/21. Final-report: baseline 77/32; min-agg 85/39; mean(done,goal,delta) 67/22. Deployment shape (ready, not shipped): the completion_review read becomes the 3-read min behind the same config gate; acceptance by held-out real-site sweep. The checker's weakness was the question, not the model.

2026-09-22 — the HISTORY frame: a pre-registered negative (deployed nothing, learned two things)

The experiment. The live failure was forgetting one's own success, and all three deployed frames read only the newest snapshot — so a fourth frame ("did the goal appear to be achieved at any point in this session?", reading the ordered page list) was the obvious candidate. Run with the no-overfit discipline the user asked for: framing, evidence rule, thresholds, cuts and the acceptance bar frozen in the script before any result existed, a mechanical vocabulary guard on the prompt, one pass over all probes, no tuning on outcomes. 815/815 reads, 0 errors.
The result: DO NOT DEPLOY. min(goal,delta,cond,hist) = 79% det / 18% FA vs min(goal,delta,cond) 78% / 17% — +0.6 det for +0.7 FA, nowhere near the pre-registered +5/−2 bar. Two mechanisms recorded: (1) the target class is small and hard — wrong failure claims are 30 of 175 wrongs and no frame catches more than 9; forgotten success is one line of evidence in thousands of characters of page noise; (2) a min-aggregate can only consume pessimism — a fourth read can never raise it, so HISTORY's genuine virtue (1.2% false alarms against phantom success) is exactly the direction a min cannot use. The cheap idea is measured and closed rather than shipped on intuition; "listen to a conservative optimist" (pessimism from ≥2 frames) is the open question it leaves.

2026-09-22 — the voting-rule test: the data caught a wrong premise, and corrected the false-alarm reading

The error, caught. A pre-registered voting experiment (pure arithmetic on the saved reads, no GPU) mislabeled the deployed rule as "all three must flag." It isn't: the gate fires when the minimum of the three verdicts dips — i.e. any single dissenter vetoes a success claim. The decomposition proves it (135 + 2 = 137 detections, split exactly along claim direction). Per the no-overfit discipline, the void comparison was retracted in place — no re-running with a new bar after peeking; nothing deployed.
The two findings that survive. (1) The vote-count dial, measured on success claims: any-one-vetoes (deployed) 93% det / 93% FA; 2-of-3 77/48; all-three 57/7 — a pure operating-point dial, no dominating rule anywhere in the frozen set. (2) The headline "17% false alarms" flatters the gate: it mixes claim directions, and on correct success claims — what a stand-down gate actually faces — the deployed rule would challenge ~93% (bench-graded), worse than the baseline read's 74%. The gate is now measurably, not just rhetorically, a "offer never assume" feature: no gate mode until a held-out real-site sweep measures the real challenge rate on correct completions.
